# Onhand Smoke Tests

This document defines the default smoke-test flows for the browser-only Onhand runtime.

These are intentionally small and repeatable. They are not exhaustive QA plans.

## Browser-Only Rules

- Start with `npm run build:extension`.
- Run `npm run test:preflight` before a merge-readiness pass.
- Start runtime checks with `npm run smoke:browser-runtime`.
- Use `npm run smoke:browser-runtime -- --ports` when browser-tool coverage is the risk.
- Use `npm run smoke:browser-runtime -- --real-openai` only when `OPENAI_API_KEY` is available and a real provider call is the goal.
- Reload the unpacked extension in Chrome after rebuilding `packages/browser-extension/onhand-runtime.bundle.js`.
- Use the extension side panel for authoritative UX checks.
- For manual Chrome model smokes, use OpenAI Codex sign-in and confirm the options status reports `aiProvider: "openai-codex"`, `aiModel: "gpt-5.5"`, and `authMode: "oauth"` before submitting from the side panel.

## Smoke 0: Browser Runtime

Use this as the default local smoke. It does not start Electron, tmux, or a localhost bridge.

### Setup

- environment: Node runtime harness
- submission path: in-extension runtime controller
- provider: deterministic `onhand-smoke` by default
- prompt: generated by `scripts/run-browser-runtime-smoke.mjs`

### What To Verify

- the browser runtime bundle imports successfully
- the Pi agent loop runs inside the browser-runtime controller
- browser tools execute and report structured page actions
- the final side-panel state is `Reply ready`
- the latest turn contains the expected reply

### Commands

```sh
npm run build:extension
npm run test:browser-runtime-regressions
npm run smoke:browser-runtime
npm run smoke:browser-runtime -- --ports
```

## Chrome Acceptance Gate

Use this before merging browser-runtime, browser-tool, side-panel, OAuth, or artifact changes that need the real Chrome extension path.

### Commands

```sh
npm run acceptance:chrome -- --suite=all
npm run acceptance:chrome -- --suite=all --run-id=chrome-acceptance-YYYY-MM-DD --json
```

See `docs/CHROME_ACCEPTANCE.md` for the current fixture and real-page prompt matrix.

## Manual Chrome UX Smokes

Run these in Chrome, not Helium, after reloading the unpacked extension from `packages/browser-extension/`.

### Article Grounding

- URL: `https://en.wikipedia.org/wiki/Personal_computer`
- prompt: ask for a short explanation grounded in the page
- verify: visible final reply, no reasoning-only final state, relevant highlight/note, page action clickthrough

### App-Like Form Page

- URL: `https://the-internet.herokuapp.com/login`
- prompt: ask Onhand to type harmless test values without submitting the form
- verify: selector/label typing works, no submit happens, final answer reports the observed state

### Client-Routed Docs Page

- URL: `https://react.dev/learn`
- prompt: ask Onhand to inspect the page and confirm what section is visible
- verify: network reload/debug tools work, headings and DOM collection are coherent

## Merge-Readiness Checklist

```sh
git diff --check origin/main...HEAD
npm run build:extension
npm run test:browser-runtime-regressions
npm run smoke:browser-runtime -- --ports --json
npm run test:preflight
npm run acceptance:chrome -- --suite=all --run-id=merge-readiness-YYYY-MM-DD --json
```

The acceptance command prints the manual Chrome prompt matrix; it does not itself drive the live OAuth side panel.
