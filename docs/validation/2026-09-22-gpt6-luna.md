# GPT-6 Luna direct OpenAI migration — September 22, 2026

## Deployed result

Onhand Free now sends text, images, and function calls to
`https://api.openai.com/v1/chat/completions` with `model: gpt-6-luna` and the
existing server-side `OPENAI_API_KEY`. The old `openai/gpt-5.6-luna` client ID
is accepted as an alias, so published extension clients receive the new model
without waiting for a store update. The rebuilt local extension displays
**Onhand Free (GPT-6 Luna)**. New inference traffic has no OpenRouter fallback.

Worker: `onhand-free-tier`.
Previous version: `c2ba293d-7168-4427-8638-4d0c5e21131c`.
Deployed version: `bd429778-75ab-4576-a4cc-0af819c3b6db`.

The complete before/after binding lists and runtime settings matched. Production
still permits 250 model calls per device/day, a $5 shared daily admission budget,
4 concurrent requests globally, 2 per device, and 50 model calls per turn. The
repository default remains 80 calls/day; deployment explicitly preserved 250.
The SQLite ledger, migration tag, KV namespace, analytics dataset, and secrets
were retained. The old OpenRouter secret serves legacy charge reconciliation only.

## Architecture and UX

The extension still talks to its hosted proxy with an anonymous device token.
The funding key stays on the Worker. Requests use Standard service, one completion,
`store: false`, `reasoning_effort: none`, and at most 16,384 output tokens.
Luna's Chat Completions function calling requires reasoning to be disabled; this
preserves the free tier's existing effective behavior. A future reasoning-enabled
agent would need a separate Responses API migration.

Text and visual requests now use one model, removing the Mistral route and its
provider switch. Conservative image compression and visual transcript budgets
remain. Prompts and browser tools were not changed for this migration.

## Cost, quality, and latency

[Official model contract](https://developers.openai.com/api/docs/models/gpt-6-luna),
[pricing](https://developers.openai.com/api/docs/pricing), and
[cache accounting](https://developers.openai.com/api/docs/guides/prompt-caching)
were retrieved on September 22, 2026.

| Standard price per million tokens | GPT-5.6 Luna | GPT-6 Luna |
| --- | ---: | ---: |
| Ordinary input | $0.20 | $0.10 |
| Cached input | $0.02 | $0.01 |
| Cache writes | $0.25 | $0.125 |
| Output | $1.20 | $0.50 |

Above 272K input tokens, the new model's full request uses 2x input/cache rates
and 1.5x output rates. Worker accounting calculates cost from final token usage,
including cache writes. These are calculated charges, not a fetched billing
invoice. Applicable credits belong to the OpenAI project behind the funding key;
its credit balance was not inspected.

The existing four-case product evaluation ran three repetitions per case:
anchored answers, browser highlighting, learning coaching, and homework refusal.
All 12 scored 1.0 with zero errors. Average response time was 1,651 ms and calculated
total cost was $0.0003939. This is a small synthetic evaluation, not proof of better
quality or latency across real research sessions or long PDFs. The historical
GPT-5.6 evaluation was not rerun as a contemporaneous comparison.

Local raw evaluation artifacts are under
`tmp/gpt6-luna-migration/2026-09-22T19-02-31Z.{jsonl,md}` (ignored).

   choice after testing. Publishing the extension and website changes remains a
   separate release step from committing and pushing the migration source.

OpenAI does not provide OpenRouter's generation-cost lookup. Missing final usage
or an exhausted settlement RPC retry leaves an unresolved reservation for that UTC
allowance day. Capacity still releases; uncertain spending is not treated as free.
Repeated cancelled requests can therefore exhaust the day's allowance earlier.
Legacy OpenRouter `gen-` records can still reconcile during seven-day retention;
official OpenAI completion IDs never go to that service.

The previous Worker version remains available for rollback. Restoring it also
requires reverting the new extension model ID, because the prior Worker only
accepts the old ID. Prefer repairing the new Worker while preserving both aliases.
